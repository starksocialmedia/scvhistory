## Can a script write the bad values back?

- `inventory/canonical_entities.json` is not the source and nothing reads it to write Craft. `scripts/import/extract_entities.py` builds it, copying each place's legacyUrl from the Craft export (`inventory/extracts/craft-entities.json`); a rerun after this fix copies the corrected values.
- The values came from `places-candidates.json`, built by `scripts/import/build_hub_candidates.py:190-204`: the first photograph page whose title category maps to a place became the place's own page. `import_places_and_series.php` copied them, but it skips any place that exists (line 46), so it cannot write them again.
- `backfill_provenance.php` fills only empty fields. For the three cleared places it finds no evidence: no WordPress post with their slug, and no entity_index entry with a legacy page. A rerun leaves them empty.
- To stop it at the source: correct or drop the seven rows in `places-candidates.json`, and change `build_hub_candidates.py` so an object page never becomes a place's legacyUrl (leave it empty). Not done here; Nathan's call.

Idempotent: a place already at its target is skipped and not saved.
